# 분석 탭 "금리 시나리오" → "금리 충격 테스트" 개편 인계

디자인 캔버스: "금리 충격 테스트 시안" (claude.ai 아티팩트, 2026-10-14 확정)
같은 폴더의 `Main.dc.html`, `Why.dc.html`, `Entry.dc.html`이 목업 원본이다. 마크업·색·간격·문구는 여기서 가져올 것.
(목업은 디자인 캔버스용 형식이라 `support.js` 없이 브라우저에서 바로 열리지 않는다. 구조와 인라인 스타일을 읽는 용도로 쓴다.)

## 왜 바꾸나

### 사용자 피드백: "이 화면이 어렵다"
- 화면이 사용자의 질문이 아니라 모델의 계산 과정을 보여 준다. 금리 → S&P 실질 이익 → 시장 기대수익 → 내 목표 확률로 이어지는 연결 고리가 안 보이고 결과만 흩어져 있다.
- 맨 위 "목표 확률 27%"는 어떤 목표인지 이 화면에 없다. "모형 범위 18%~32%"는 확률의 범위라 일반 사용자에게 너무 어렵다. "금리 영향 빼면 35%"는 좋은 정보인데 차이(−8%p)로 말해 주지 않는다.
- 그래프가 내 돈이 아니라 S&P500 실질 이익(오늘=100)이다. y축 숫자가 없고 "모형 80%가 드는 범위"라는 통계 표현을 쓴다.
- 10년물, %p, 실질 이익, "시장 공통 기대수익(금리 외 요인, 연)" 같은 용어가 그대로 보인다. 슬라이더 기본값은 +0%인데 표의 시장 기대수익은 −1.3%라서 서로 다른 숫자처럼 보인다.
- 표에 숫자가 약 20개 있다. "감소" 열이 '감소할 확률'이라는 설명이 없어서 "2년째 감소 97%"가 공포스럽게 읽힌다. 헤더 정렬도 어긋나 "중앙 상위 10%"가 한 덩어리처럼 붙어 보인다.
- 레이아웃 버그: 고정 머리(`pinnedBox`) 아래로 "앞으로 1년 10년물 금리 변화" 글자가 잘려 겹친다.

### 다른 화면과 겹친다 (차별화 필요)
| | 내 목표(내 길) | 목표일 전망 | 금리 시나리오(지금) |
|---|---|---|---|
| 답하는 질문 | 언제 닿을까? | 목표일에 얼마일까? | 불분명 (목표 확률은?) |
| 조절하는 것 | 포트폴리오 구성 | 시장에 대한 믿음 | 금리 + 시장 기대수익 |
| 핵심 숫자 | "반반이에요" | 10억 넘을 확률 36% | 목표 확률 27% |
| 범위 표현 | 10번 중 8번/5번 | 10번 중 5번/9번 | 모형 80%, 하위 10% |

- 같은 목표에 확률이 세 개(반반 / 36% / 27%)라서 앱이 스스로 모순되는 것처럼 보인다.
- "시장 공통 기대수익" 슬라이더는 목표일 전망의 "지난 3년 추세를 얼마나 믿나요"와 역할이 같은 레버다.
- 시안 캡처에서 현재 자산이 5.16억과 3.30억으로 다르게 찍혀 있었다. 테스트 데이터가 아니라면 맞춰야 한다 (확인 필요).

### 정한 방향: "전망"이 아니라 "충격 테스트"
다른 두 화면은 "내 계획대로 가면 어떻게 되나"를 보여 준다. 이 화면은 **"금리라는 외부 충격이 오면 내 계획이 얼마나 흔들리나"** 만 답한다.
1. 절대값 대신 **변화량**: 목표일 전망 결과를 기준선으로 두고 차이만 보여 준다 (36% → 27%, −9%p).
2. 슬라이더 대신 **이야기가 있는 프리셋 4개**. 세밀한 조절은 "직접 정하기" 안으로 넣는다. "시장 공통 기대수익" 슬라이더는 이 화면에서 뺀다.
3. **원인 사슬**(금리 → 기업 이익 → 내 자산)을 화면의 주인공으로. S&P 이익 그래프·표는 근거 화면으로 내린다.
4. **내 종목 중 금리에 약한 곳**을 보여 주고 "구성 바꿔서 다시 테스트하기"로 행동을 잇는다.
5. 목표일 전망의 금리 일정과 **연결**한다 (진입점).
6. 범위 표현은 앱 전체에서 "10번 중 N번"으로 통일한다.

## 화면별 구성 (위 → 아래)

### 1. 메인 — `Main.dc.html` (390×2080, 동작하는 목업)
1. **머리**: 뒤로 버튼 + 제목 "금리 충격 테스트".
2. **질문형 제목**: "금리가 이렇게 되면, 내 목표는 얼마나 흔들릴까요?" + 설명 "목표일 전망의 **내 설정**을 기준으로, 금리만 바꿔 봤을 때 달라지는 만큼만 보여줘요."
3. **프리셋 4개** (2×2 버튼, 하나 선택, 기본은 "작년만큼 또 오른다"):
   - 내린다 (10년물 −0.5%p) / 그대로 (변화 없음) / 작년만큼 또 오른다 (+1.1%p) / 2022년처럼 급등 (+2.5%p)
4. **결과 카드 (어두운 배경)**:
   - 상황 문장 ("금리가 작년만큼 또 오르면")
   - "목표 가능성 36% → **27%**" + 변화 알약 (−9%p는 주황, +는 청록, 변화 없음은 회색)
   - 막대 두 줄: 지금 / 이 경우
   - "10억에 닿는 시점: 약 6개월 늦어져요", "2029년 10월 그럴듯한 금액: 7.39억 → 6.71억"
5. **"어떻게 내 자산까지 오나요?"** 세로 3단계:
   1) 금리: 5.24% → 6.34% (미국 10년물 국채 금리 기준)
   2) 기업이 버는 돈: 3년 동안 이익이 약 9% 줄어요
   3) 내 자산: 1년 기대수익이 약 1.3%p 낮아져요
   - "2단계 근거 자세히 보기" → 근거 화면
6. **"내 종목 중 금리에 약한 곳"**: 보유 종목을 민감도 순으로 막대 + "크게 흔들려요 / 덜 흔들려요" + 비중·성격. 버튼 "구성 바꿔서 다시 테스트하기".
7. **"다가오는 금리 일정"**: FOMC, 한국은행 날짜 + 토글 "결정 하루 전에 이 테스트 다시 보기".
8. **"금리 변화 직접 정하기"** (접힘): 펼치면 기존 금리 슬라이더 (−2 ~ +3%p).
9. 안내문: "예측이 아니라 '만약에'를 보는 화면이에요. 금리 말고 다른 조건은 목표일 전망의 내 설정과 같아요."

### 2. 근거 — `Why.dc.html` (390×1300)
1. 머리: 뒤로 + "근거 자세히 보기".
2. 머리글 "2단계 · 기업이 버는 돈" + 제목 "금리가 작년만큼 또 오르면, 미국 대표 기업들의 이익은 이렇게 움직여요" + "S&P500 이익을 오늘 100으로, 물가를 뺀 값".
3. **그래프**: y축 숫자(70~110) 있음, 오늘 수준 점선, 보통의 경우 선, 10번 중 8번 띠, 끝값 라벨. 범례 포함.
4. **표 (3행 × 3열)**: 1년 뒤 / 2년 뒤 / 3년 뒤 × 보통 / 10번 중 8번 / 줄어들 확률. 지금의 "해마다 변화"가 아니라 **오늘 대비 누적 수준**으로 통일. 아래에 "줄어들 확률은 그 시점 이익이 오늘보다 적을 가능성이에요."
5. **"읽는 법"** 3문장: 첫해는 버틴다 / 2년째 가장 크게 준다 / 3년째는 범위가 넓다.
6. 버튼 "내 목표 영향으로 돌아가기".
- 지금의 "시장 연 기대수익" 행과 β 문구는 화면에서 뺀다 (필요하면 안내문 수준으로).

### 3. 진입점 — `Entry.dc.html` (목표일 전망 화면의 일부)
- 목표일 전망의 "전망을 흔들 수 있는 일정" 목록에서 **금리 일정(한국은행, FOMC) 행 아래에만** "금리가 오르면 내 목표는? 미리 보기" 버튼을 붙여 이 화면으로 보낸다. 실적 발표 행에는 없다.

## 목업과 실제 구현의 차이

### 숫자는 전부 예시
- 프리셋별 결과(39% / 36% / 27% / 18%, 시점 변화, 금액, 이익 변화, 기대수익 변화)는 **화면 흐름을 보여 주려고 넣은 예시**다. 실제로는 계산해서 넣는다.
- 기준값 36%·7.39억은 목표일 전망 캡처의 '내 설정' 값을 빌린 것이다.
- `[보유 종목 N]`, `[00]%`, `[날짜]` 대괄호는 전부 실제 데이터 자리.

### 계산 연결 (지금 코드 기준, 확인 필요)
- 앱: `ios-app/Naeilo/Views/AnalysisDetail.swift`의 `RateScenarioView`, `MacroData`, `RateScen`, `RateBandChart`. 탭 이름·순서는 `AnalysisView.swift`(`AnalysisRoute.rateScen`, 카드 머리 `rateTag`).
- 웹: `web/app.js`의 "금리 시나리오" 섹션(`// ---- 금리 시나리오`, `RS` 상태, `#sec-rs`). CLAUDE.md 규칙상 같은 화면의 앱 숫자는 웹 기본 결과와 같아야 하므로 웹 범위를 정해야 한다.
- **기준선 36%**: 지금 코드의 `base = prob(f, ci, 0)`은 `m.forecast.pGoal`(목표일 전망)이다. 목업이 말하는 "목표일 전망의 내 설정"(추세 믿음 슬라이더 값 반영)과 같은 값인지 확인해야 한다. 다르면 문구를 실제 기준에 맞춘다.
- **변화 후 확률**: 지금 `pb[1]`(식단 1000벌의 중앙) 계산을 그대로 쓰면 된다. 단 `mk`(시장 공통 기대수익)는 0으로 고정하고 슬라이더를 없앤다.
- **프리셋 → dr 값**: "작년만큼"은 `MacroData.defaultDr`(지난 1년 실제 변화)을 쓴다. 다른 세 값(−0.5, 0, +2.5)은 고정값으로 할지, "2022년처럼"을 실제 데이터에서 뽑을지 정해야 한다.
- **새로 계산해야 하는 것** (지금 코드에 없음):
  - 10억에 닿는 시점 변화 (몇 개월 빨라짐/늦어짐)
  - 목표일 그럴듯한 금액 변화 (기준 → 이 경우)
  - 3단계의 "1년 기대수익 변화" (`kb * (b*d/3/100)` 중앙값으로 근사 가능해 보임)
- **금리에 약한 종목**: `ExternalView.coef(sym)`가 "미국 10년 금리 +1%p일 때 %"를 이미 갖고 있다(AnalysisDetail.swift 335행 주석). 이 값으로 정렬하고 3단계 문구(크게/덜 흔들려요)로 나눈다. "종목+금액+시점" 조언 금지 규칙에 맞게 비율·민감도로만 보여 준다.
- **근거 화면 표**: 지금은 해마다 변화(`yr`)와 3년 누적(`cum`)이 섞여 있다. 목업은 모두 **오늘 대비 누적 수준**(`100·exp(cum/100)`)과 그 시점 **누적 감소 확률**로 바꾼다. 해마다 누적 감소 확률은 지금 `dropCum`이 끝 해만 있으니 해마다 계산이 필요하다.
- **알림 토글**: 금리 결정일 데이터와 로컬 알림이 필요하다. 일정 데이터를 어디서 받는지(목표일 전망의 일정 목록 출처) 확인 후, 없으면 이 항목은 다음 단계로 미룬다.
- **"구성 바꿔서 다시 테스트하기"**: 내 길 개편(B-2 비중 비교, `docs/handoff/Compare.dc.html`)과 연결할지, 일단 숨길지 정해야 한다.

### 디자인 차이
- 목업은 고정 높이 아트보드다. 실제는 스크롤 화면이고, 지금의 고정 머리(`PinnedLayout`)는 쓰지 않는다 (겹침 버그 원인).
- 색은 기존 Theme에 맞춘다: 어두운 카드 = 기존 `Card(dark:)`, 청록 = `Theme.teal`, 주황 = `Theme.orange` 계열. 목업 hex(#1b2030, #2b6b5f, #c8692a 등)는 참고용.
- 폰트는 목업이 Noto Sans KR이지만 앱 `appFont`를 그대로 쓴다.
- 탭 이름 "금리 시나리오" → "금리 충격 테스트"로 바꿀지는 사용자 결정 (분석 카드 목록 문구 `"금리가 움직이면 시장 이익과 내 목표는"`도 같이).
