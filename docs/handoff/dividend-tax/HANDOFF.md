# 분석 탭 "배당·세금" 화면 개편 — 확정안 인계

디자인 캔버스: "배당·세금 화면 개선 시안" (claude.ai 아티팩트, 2026-10-14 확정)
같은 폴더의 목업 원본(390px 폰 화면):
- `Main.dc.html`: ① 받는 배당 (달별/종목별 전환이 동작함)
- `Tax.dc.html`: ② 낼 양도세 (슬라이더가 동작함)

두 파일 모두 위쪽 탭으로 서로 오간다. 문구·순서·간격은 여기서 가져오되, 글꼴과 색은 앱의 `appFont`·`Theme`에 맞춘다. 목업의 하단 탭바(홈·종목·분석·미션·설정)는 생략했을 뿐이고 그대로 둔다.

대상 코드: `ios-app/Naeilo/Views/AnalysisDetail.swift`의 `DividendView` (`// MARK: 배당·세금`).
분석 탭 목록 카드: `ios-app/Naeilo/Views/AnalysisView.swift`(`case .dividend`, "앞으로 12개월 배당, 팔 때 세금").
계산: `ios-app/Naeilo/Data/SiteCalc.swift` (`project`, `div`, `capGainTax`, `wht`·`krDivTax`·`cgt`·`cgtDed`).
웹의 같은 계산: `web/app.js` `// ---- 배당·세금` (`dividends`, `divGrowth`, `renderCash`). 웹은 종목 탭 안에 있다.

## 왜 바꾸나 (사용자 피드백: "일반 사용자는 어렵다")
1. **한 화면에 질문이 두 개**: 들어오는 돈(배당, 작고 미래)과 나가는 돈(양도세, 크고 일부 확정)이 섞여 있다. 가장 큰 숫자가 55만원(배당)이고, 더 중요한 375만원(내년 세금)은 아래 어두운 카드 안에 묻혀 있다.
2. **시간 기준이 네 개**: "앞으로 12개월", "올해 이미", "내년 5월", "3년 합계"가 한 화면에 섞여 있다.
3. **숫자에 설명이 없음**
   - 요약줄 `세전 65만원 · 월평균 5만원 · 평가액의 0.11% · 3년 합계 165만원`은 기준이 다른 숫자 4개를 점으로 이은 것이다. 월평균이 세후(`net/12`)인데 세전처럼 읽히고, `won1` 반올림 때문에 5만원으로 보인다(실제 약 4.6만원).
   - 3년 합계가 정확히 55×3으로 보여 "증가율만큼 늘며"라는 각주와 어긋나 보인다(증가율이 0이면 그렇다).
   - 종목별 `2회 · 0.22%`에 라벨이 없다.
   - 달별 차트에 값·연도 표시가 없고, 6·9월이 큰 이유도 없다.
   - `375만원 / 5,028만원`은 두 시나리오를 슬래시로 붙여 해석이 안 된다.
4. **개발자 언어**: "세금 규칙에 넣은 값", "(웹과 같은 계산)", "매매기준율 기준", "금융소득 종합과세".
5. **내 상황과 무관한 규칙**: 국내 주식이 없는데 "국내 종목·국내 상장 ETF 배당 15.4%" 줄이 보인다.
6. **조작 요소**: '달마다/종목별'이 차트 아래에 꽉 찬 큰 버튼이라 실행 버튼처럼 보인다.
7. **결론이 없다**: "그래서 내년 5월에 얼마 내고, 지금 뭘 알아야 하나"를 사용자가 직접 조합해야 한다.

## 확정 화면 구성 (위 → 아래)

### 공통 머리
1. 뒤로 버튼 + 제목 "배당·세금". 제목 아래 기존 부제("앞으로 12개월 받을 배당과, 팔 때 낼 세금")는 뺀다.
2. **화면 전환 탭 2개**: "받는 배당" | "낼 양도세" (세그먼트 형태, 선택된 쪽이 흰 배경+굵게). 같은 화면 안의 전환이다(새 화면 push 아님).

### ① 받는 배당 (`Main.dc.html`)
1. **요약 카드**
   - 작은 줄: "앞으로 1년 · {YYYY년 M월} ~ {YYYY년 M월}"
   - 큰 문장: "한 달에 평균 / **약 {월평균 세후}**이 / 배당으로 들어와요"
   - 아래 줄: "1년 합계 **{세후 1년}** · 세금 떼고 실제로 받는 돈"
2. **달별/종목별 전환** (요약 바로 아래, 차트 위). 작은 세그먼트: "달별로 보기" | "종목별로 보기"
3. **달별로 보기**
   - 막대 12개. 큰 달(위 몇 개)만 막대 위에 금액 라벨("11.4만"). 가장 큰 달들은 진한 색, 나머지는 옅은 색.
   - x축 월 숫자 + 그 아래 **연도 구간 표시**(2026년 | 2027년).
   - 차트 아래 설명 목록(점 2개): 큰 달이 왜 큰지("6월·9월이 많은 건 NVDA 배당이 같이 들어와서예요"), 평소 달은 얼마인지, 배당이 없는 달이 있으면 그 달.
4. **종목별로 보기**
   - 종목마다: 티커 + 쉬운 이름(회색), 오른쪽 세후 1년 금액, 막대, 아래 설명 "{매달 들어와요 | 1년에 N번(M월·M월)} · 1년에 투자금의 {배당률}%"
   - 맨 아래 회색 박스: "{배당 없는 종목들}은 배당을 주지 않아서 목록에 없어요."
5. **"세금은 이미 빠진 금액이에요" 카드** (영수증 형태)
   - 배당 원래 금액 {세전} / 미국에서 떼는 세금 15% −{세금} / 구분선 / **내 계좌에 들어오는 돈 {세후}**
   - 아래: "미국 주식 배당은 한국에서 세금을 더 내지 않아요."
6. **"1년 배당·이자가 2,000만원을 넘으면 세금 계산이 달라져요" 카드**
   - 진행 막대(세전 1년 / 2,000만원)
   - "지금 **{세전}**" · "기준까지 {남은 금액} 남음"
   - 초록 박스: "지금은 걱정 없어요. 은행 예금 이자도 이 2,000만원에 같이 들어가요."
7. **"이 숫자는 어떻게 계산했나요?" 접이식** (기본 접힘): 지난 12개월 배당이 같은 달에 오고 지난 3년 증가 속도만큼 늘어난다고 본 값, 실제와 다를 수 있음, 세무 상담 아님.

### ② 낼 양도세 (`Tax.dc.html`)
1. **요약 카드**
   - 작은 줄: "올해 판 미국 주식 기준"
   - 큰 문장: "내년 5월에 / **약 {세금}**을 / 세금으로 내야 해요" (세금 강조색은 주황 계열)
   - 설명: "올해 미국 주식을 팔아 남긴 이익 때문이에요. 12월 31일 전에 더 팔면 늘어나요."
   - 회색 줄(달력 아이콘): "신고·납부 **{내년}년 5월 1일 ~ 31일**"
   - **나눔 막대**: 올해 판 이익 중 250만원까지(세금 없음, 옅은 초록) | 나머지(22%, 옅은 주황) + 범례 2개
   - **영수증**: 올해 판 이익 / 세금 없는 몫 −250만원 / 세금 붙는 이익 / 세율(지방세 포함) × 22% / 구분선 / **낼 세금**
2. **"올해 더 팔면 세금은 얼마?" 카드** (기존 `375만원 / 5,028만원` 한 줄을 대체)
   - 설명: "아직 안 판 미국 주식에 **{평가 이익}**의 이익이 있어요 ({종목들})."
   - 라벨 "추가로 팔 이익" + 현재 값, 슬라이더(0 ~ 평가 이익 전부), 양끝 "안 팔면" / "전부 팔면"
   - 결과 박스: "내년 5월 낼 세금 **{값}**"
   - 아래 한 줄: 0일 때 "지금 그대로면 이 금액이에요.", 아니면 "지금보다 약 {차이} 늘어요."
3. **"연말 전에 알아두면 좋은 것" 카드** (번호 3개) — 아래 "확인할 것" 참고
   1. 손해 본 종목이 있으면 올해 안에 팔 때 그 손해만큼 이익에서 빠진다
   2. 더 팔 계획이 있으면 내년 1월 이후로 미루면 내년 몫 250만원을 새로 쓴다
   3. 미국 주식은 결제일 기준이라 12월 마지막 거래일 1~2일 전까지 팔아야 올해로 잡힌다
4. **"이 숫자는 어떻게 계산했나요?" 접이식**: 올해 판 이익은 앱에 입력한 값, 안 판 이익은 환율을 적용해 원화로 계산, 국내 상장주식은 대주주가 아니면 양도세 없음(거래세만), 세무 상담 아님.

### 빠지는 것
- 요약줄 `세전 · 월평균 · 평가액의 % · 3년 합계` (요약 문장과 영수증이 대신함. 3년 합계는 화면에서 뺀다)
- 보유 종목과 무관한 "국내 종목·국내 상장 ETF 배당 15.4%" 줄(조건부로만, 아래 참고)
- "세금 규칙에 넣은 값", "(웹과 같은 계산)", "매매기준율 기준", "금융소득 종합과세" 문구
- 어두운 양도세 카드와 `지금 그대로 / 미국 종목 다 판다면` 슬래시 줄

## 목업과 실제 구현의 차이 (목업 숫자를 그대로 쓰지 말 것)
- **숫자는 전부 하드코딩**: 55만원·65만원·10만원, 달별 금액(2.9만·6.5만·11.4만), 종목별 38만·17만, 1,953만원·2억 1,150만원은 스크린샷에서 옮기거나 **막대 높이로 어림한 값**이다. 실제는 지금 `DividendView`의 값(`net`, `gross`, `byMonth`, `paid`, `G = m.taxGain*1e4`, `usU`)을 그대로 쓴다. 계산식은 바꾸지 않는다(웹과 같아야 함, parity 도구 `calc_parity` 대상).
- **세금 계산**: 목업 스크립트의 `max(0, 1953 + extra − 250) × 0.22`는 `SiteCalc.capGainTax(G + extra)`와 같은 식. 실제는 `capGainTax`를 쓴다.
- **슬라이더 범위**: 0 ~ `usU`. `usU <= 0`(평가 손실이거나 매수 단가가 없음)이면 슬라이더 카드를 숨기거나 "아직 안 판 이익이 없어요"로 바꾼다. 손실일 때 기존 안내("손실은 확정된 해의 이익과 합쳐 계산돼요…")를 어디에 둘지는 계획에서 제안.
- **`G == 0`(올해 판 이익 없음)**: 요약 문장을 "올해 판 이익이 없어서 내년 5월에 낼 양도세가 없어요" 같은 형태로 바꾸고, 나눔 막대·영수증을 숨기는 등 빈 상태를 계획에서 정한다. `G <= 250만원`이면 "250만원까지는 세금이 없어 낼 세금이 없어요".
- **월평균 문구**: 목업 "약 4만 6천원"은 55만÷12. 실제는 `net / 12`를 "약 N만 M천원"처럼 읽기 쉬운 형식으로. `AppModel`에 맞는 포맷 함수가 없으면 새로 만든다. 웹 숫자 규칙(같은 값)은 지키되 표기만 다르다.
- **기간 줄**: "2026년 11월 ~ 2027년 10월"은 `months` 첫·끝 값으로 만든다.
- **달별 막대 강조·라벨**: 목업은 큰 달 3개에 라벨, 6·9월만 진한 색. 규칙을 정해야 함(예: 최대값의 1.5배 이상인 달 또는 위 2~3개). 배당이 0인 달은 지금처럼 2px 회색 막대.
- **연도 구간 표시**: 12개월이 두 해에 걸치면 해마다 구간 표시. 연도가 하나면 하나만.
- **차트 아래 설명 문장**: 목업 문장은 이 사용자의 보유 종목에 맞춘 예시. 실제는 데이터로 만든다 — 큰 달이 생기는 종목(`byMonth`를 종목별로 나눠 보면 알 수 있음), 평소 달 금액, 0원인 달. 문장을 만들기 애매하면(종목이 많아 큰 달 원인이 여럿 등) 문장을 줄이거나 빼는 기준을 계획에서 제안.
- **종목별 설명**: "매달 들어와요"는 `n == 12`, 나머지는 "1년에 N번(M월·M월)". 지급 월 목록은 지금 `DivOut`에 없을 수 있으니 확인. 쉬운 이름(엔비디아, 미국 단기국채 ETF)은 `StockCatalog` 등 기존 이름 자료가 있으면 쓰고 없으면 생략.
- **배당 없는 종목 안내**: 지금의 `zero`(배당 없음)·`unknown`(시세 자료 없음) 목록을 쓴다. 기존 `net < 10만원`일 때 뜨던 크림색 안내 문구("지금 구성은 배당이 적어요…")를 이 박스로 합칠지 계획에서 정한다.
- **국내 배당 세금**: 목업은 미국 종목만 있는 경우. 국내 종목(`currency == .krw`)을 갖고 있으면 영수증에 "국내에서 떼는 세금 15.4%" 줄을 추가하는 식으로 조건부 표시. 문구 "미국 주식 배당은 한국에서 세금을 더 내지 않아요"도 미국 종목이 있을 때만.
- **2,000만원 카드**: 목업 막대 폭 4%는 어림. 실제는 `gross / 2000e4`. 넘었으면(`gross >= 2000e4`) 초록 안심 박스 대신 주의 문구로 바꾼다(문구는 계획에서 제안).
- **"신고·납부 2027년 5월 1일 ~ 31일"**: 올해+1년으로 계산. 5월 31일이 주말이면 다음 영업일로 밀리는데, 화면에는 "5월 1일 ~ 31일"로 단순하게 둔다(계획에서 이견 있으면 제안).
- **화면 전환 탭**: 목업은 두 파일이 링크로 오가지만 실제는 한 `DividendView` 안 `@State` 하나로 전환. 기존 `mode`(달마다/종목별)와 별개 상태가 하나 더 생긴다. 분석 탭 목록 카드나 다른 곳에서 "낼 양도세" 쪽으로 바로 들어오는 경로가 필요한지 계획에서 판단.
- **고정 영역**: 지금은 `PinnedLayout`으로 머리+차트+요약줄+토글을 고정한다. 새 구성에서 무엇을 고정할지(예: 제목+전환 탭만) 정해야 함.
- **분석 탭 목록 카드**(`AnalysisView.swift`): 부제 "앞으로 12개월 배당, 팔 때 세금"과 값 "연 {div}"는 그대로 둬도 되지만, 새 화면과 말투를 맞출지 계획에서 제안.
- **색**: 세금 강조 주황(#C2410C 계열)·옅은 주황 막대는 목업용. `Theme`에 비슷한 색이 있으면 그걸 쓴다. 앱의 손익 색 규칙(`Theme.change`: 늘면 빨강, 줄면 파랑)과 헷갈리지 않게, "세금"은 손익 색을 쓰지 않는다.
- **웹**: 웹의 배당·세금(종목 탭 `renderCash`)은 이번 범위가 아니다. 숫자 계산만 같으면 된다. 웹도 같은 구성으로 바꿀지는 별도 스레드.

## 확인할 것 (계획 단계에서 사용자에게 물어볼 것)
- **"연말 전에 알아두면 좋은 것" 3개와 CLAUDE.md 규칙**: "화면에 '종목 + 금액 + 시점' 조언을 쓰지 않는다"와 부딪히는지. 목업 문구는 특정 종목·금액을 말하지 않는 일반 세금 규칙이지만 "올해 안에", "1월 이후로" 같은 시점이 들어 있다. 그대로 넣을지, 사실 설명 말투로 바꿀지("손실은 같은 해 이익에서 빠져요", "250만원 공제는 해마다 새로 생겨요") 사용자에게 확인한다. 기존 화면의 "매매 권유가 아니에요" 안내를 유지할지도.
- **3번(결제일)의 사실 확인**: 미국 주식 매도의 과세 연도 기준(결제일)과 국내 증권사 기준 결제일(현지 T+1 → 국내 날짜로 며칠)을 확인한 뒤 문구를 확정한다. 확인이 어렵다면 3번은 빼는 쪽을 제안.
