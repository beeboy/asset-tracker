# 분석 탭 "환율 영향" 화면 개편 — 확정안 인계

디자인 캔버스: "환율 영향 화면 개선안" (claude.ai 아티팩트, 2026-10-14 확정)
개인 정보 보호: 이 폴더의 금액·목표는 모두 가상의 예시값이다. 실제 사용자 숫자는 저장소에 쓰지 않는다.
같은 폴더의 `Main.dc.html`이 목업 원본이다(390px 폰 화면, 슬라이더·칩·기간 탭·자세히 보기가 동작함). 문구·순서·간격은 여기서 가져오되, 글꼴과 색은 앱의 `appFont`·`Theme`에 맞춘다.

대상 코드: `ios-app/Naeilo/Views/AnalysisDetail.swift`의 `FxImpactView` (`// MARK: 환율 영향`).
웹에도 같은 화면이 있다: `web/app.js` 전망 탭(`// 전망 탭: 목표일 전망 · 외부 요인 · 환율 영향을 한 화면에`, `fxInfo()` 부근).

## 왜 바꾸나 (사용자 피드백: "일반 사용자는 어렵다")
1. **전문 용어 그대로 노출**: 칼만 추세, 5~95%, 중앙값, 변동성(연), 기울기 연 −5.4%, 전망 모형 적용 값, "원화 평가액에 더해진 몫(근사)". 하단 각주는 개발자 메모 수준.
2. **방향을 머릿속에서 뒤집어야 함**: 달러 자산이면 "환율 하락 = 내 자산 감소"인데 이 문장이 어디에도 없다. "환율 1%면 [금액]"(부호 없음), "원화 10% 강세면 −[금액]"(원화 기준), "하락 추세"(좋은지 나쁜지 모호)가 섞여 있다.
3. **같은 값이 다르게 나옴**
   - 지금 환율: 머리 1,339원(`FX`) / 표 "1,340원 (지금)"(`Int(BASE)` 버림) / 슬라이더 시작 1,341원(`valFx.rounded()`). 슬라이더를 안 건드렸는데 "+[금액]" 변화가 뜬다.
   - 1년 변화: 머리 "1년 동안 −6.7%"(`past` 첫 값 기준 `chg`) / 카드 −6.9%(`c.ret_1y`).
   - "지난 1년 환율 효과"와 "1년 변화" 카드가 사실상 중복(달러 비중 100%면 같은 값).
4. **차트 단서 부족**: y축 눈금 없음, 띠 끝 값 없음, 검은 선과 주황 추세선이 겹쳐 구분 안 됨. 3년 중앙값 카드는 범위가 999~1,746원이라 "아무것도 모른다"는 인상.
5. **범례 글자 깨짐(버그)**: "앞으로 1년 25~75%(진함)·5~95%"가 취소선으로 보인다. SwiftUI `Text("...")` 문자열 리터럴이 마크다운으로 해석되어 `~...~`가 취소선이 된 것으로 보인다 → `Text(verbatim:)`로 고칠 것. 이 파일의 다른 `~` 들어간 문구도 함께 확인.
6. **결론 없이 숫자 나열**: 카드 6개 + 슬라이더 + 표 5줄이 같은 무게. 표의 모든 줄에 "목표까지 ○억"이 반복되고 줄바꿈도 들쭉날쭉.

## 확정 화면 구성 (위 → 아래)
1. **머리**: 뒤로 버튼 + 제목 "환율 영향". (기존 부제 "달러 자산 비중 · 환율 1%면 …"는 뺀다)
2. **한 줄 요약 카드 (어두운 배경)**
   - 작은 제목 "한 줄 요약"
   - 큰 문장 "환율이 10원 내리면 / 내 자산은 약 {10원당 변화} 줄어요"
   - 설명 "내 주식은 모두 달러라서, 환율이 내려가면(원화가 강해지면) 원화로 본 금액이 줄어요. 반대로 환율이 오르면 늘어요."
   - 알약 2개: "요즘 흐름 · {내려가는 중|오르는 중|옆으로}", "1년 전보다 {±x.x%}"
3. **환율 카드 (흰 배경)**
   - "지금 원/달러 환율" + 큰 숫자(한 값만), 오른쪽 "M월 D일 기준"
   - 차트: 왼쪽 y축 눈금(100원 단위 등 깔끔한 값), 지난 환율 검은 선, 오늘 세로 점선 + 파란 점, 앞으로 1년 띠 두 겹, **띠 오른쪽 끝에 4개 값 라벨**. 주황 추세선은 뺀다. x축 "{기간} 전 / 오늘 / 1년 뒤".
   - 범례 3줄: "지난 1년 실제 환율", "1년 뒤, 둘 중 하나는 이 안 (a~b원)"(25~75%), "1년 뒤, 열에 아홉은 이 안 (c~d원)"(5~95%)
   - 기간 탭 1개월 · 3개월 · 1년 · 3년 (지난 선의 길이만 바뀜, 띠는 늘 1년)
4. **"환율이 바뀌면 내 자산은?" 카드**
   - 부제 "주가는 그대로라고 가정해요"
   - 결과 박스: "환율이 {r}원이 되면" / 평가액 / "지금보다 {x} 늘어요|줄어요|지금과 같아요"(늘면 빨강, 줄면 파랑, 같으면 회색 — 앱 `Theme.change` 규칙)
   - 슬라이더 (시작값 = 지금 환율, 시작 상태에서 변화 0)
   - 빠른 선택 칩 5개: 1,250 · 1,300 · **지금** · 1,450 · 1,500 → 기존 "환율별 내 평가액" 표를 대체
   - 구분선 아래 목표 1줄: "{목표 이름}까지 {남은 금액} 남음" + 진행 막대 (표마다 반복하던 "목표까지"는 여기 한 번만)
5. **"자세히 보기" 접이식 (기본 접힘)**: 2×2 칸
   - "1년 동안 오간 범위" (기존 1년 범위)
   - "1년간 출렁인 정도" → "보통 (연 9.8%)" (낮음/보통/큼 말 + 숫자)
   - "3년 뒤 가장 그럴듯한 값" (기존 목표일 환율 중앙값 — 목표일 기준이면 제목을 목표일에 맞춤)
   - "환율 때문에 생긴 1년 손익" (기존 지난 1년 환율 효과)
   - 아래 안내 1줄: "예상 범위는 지난 환율의 흐름과 출렁임으로 계산한 값이라 실제와 다를 수 있어요."
   - 빠지는 것: 칼만 추세값·기울기, "원화 10% 강세면" 카드(요약 문장과 슬라이더가 대신함), 개발자용 각주.

## 목업과 실제 구현의 차이 (목업 숫자를 그대로 쓰지 말 것)
- **숫자는 전부 하드코딩**: 목업 스크립트의 `NOW = 1339`, `BASE = 30000`(만원, 가상의 평가액 3억), `GOAL = 50000`(가상의 목표 5억), 비례식 `BASE * rate / NOW`는 예시다. 실제는 기존 식 `valAt(r) = m.total + usdV * (r / BASE − 1)`을 쓴다(웹 fxBase와 같은 기준이어야 함).
- **"지금 환율" 하나로 통일**: 화면에 보이는 지금 값·슬라이더 시작값·"지금" 칩·변화 0 기준을 모두 같은 값으로. 표시 값(`FX`, 지금 환율)과 계산 기준(`BASE`, 매매기준율)이 다른 문제를 어떻게 풀지는 계획 단계에서 정한다(예: 계산 기준을 화면에 쓰거나, 지금 상태의 변화를 0으로 고정). 웹과 같은 숫자 규칙(CLAUDE.md)을 깨지 않는 쪽으로.
- **"1년 전보다"**: 한 가지 출처(`c.ret_1y` 권장)로 통일. 지금 머리줄의 `chg`(기간 선택에 따라 바뀜)와 섞지 않는다.
- **차트 선과 띠**: 목업의 지난 선은 스크린샷을 보고 그린 대충의 모양, 띠 값(1,250~1,430 / 1,130~1,560)은 연 변동성 9.8%로 어림한 값이다. 실제는 기존 `q(±0.674)`, `q(±1.645)`의 t=1 값을 쓰고, 라벨도 그 값으로.
- **y축**: 지금은 `hi/lo` 자동 범위. 깔끔한 눈금 값(예: 50·100원 단위)을 골라 그린다.
- **달러 비중 100% 가정**: 목업 문구는 "내 주식은 모두 달러라서". 실제는 `usdW`에 따라
  - 100%: 목업 문구
  - 0% 초과~100% 미만: "내 자산 중 {비중}이 달러라서 …"
  - 0%: 요약 카드 대신 "달러 자산이 없어 환율 영향이 없어요" 등 (계획에서 제안)
- **10원당 변화**: `usdV * 10 / BASE` (목업은 가상 평가액 3억 기준 224만원 예시).
- **추세 알약**: 지금 `c.trend` 문구("하락 추세" 등)를 쉬운 말로 바꿔 보여 줌. 매핑은 계획에서 제안.
- **목표**: 목업은 가상의 목표(5억)로 고정. 실제는 `m.keyName` / `m.keyValue`.
- **슬라이더**: 목업 1,100~1,600·1원 단위, 앱 1,200~1,600·10원 단위. 범위·단위는 계획에서 정하되 칩 값(1,250 등)과 지금 값이 슬라이더 위에 올 수 있어야 함.
- **고정 영역**: 앱은 `PinnedLayout`으로 머리+차트를 고정한다. 목업 순서(요약 카드가 차트 위)와 맞추려면 고정 영역에 무엇을 둘지 정해야 함.
- **글꼴·색**: 목업의 IBM Plex Sans KR과 헥스 색은 목업용. 앱 `appFont`, `Theme.blue/down/change/sub/muted`, `Card(dark:)`, `ChipRow`를 쓴다.
- **웹**: 같은 화면이 웹 전망 탭에 있다. 이번 인계는 앱 화면 기준. 웹도 맞출지, 계산이 바뀌는지(바뀌면 웹·parity 도구까지)는 계획에서 나눠 제안한다. 한 스레드 한 화면 규칙에 따라 웹은 별도 스레드로 두는 안을 기본으로.
