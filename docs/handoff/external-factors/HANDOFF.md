# 분석 탭 "외부 요인" 화면 개편 — 인계

디자인 캔버스: "외부 요인 개편안" (claude.ai 아티팩트, 아트보드 2개)
같은 폴더의 `Main.dc.html`(외부 요인 메인), `Factor.dc.html`(요인 상세 — 미국 금리 예시, 프리셋 버튼이 동작하는 목업)이 확정 목업 원본이다. 마크업·색·간격·문구는 여기서 가져올 것.
나란히 보는 화면: `docs/handoff/HANDOFF.md`(내 길 B안). 같은 디자인 언어(흰 카드 + 어두운 판정 카드 + 초록 강조, "10번 중 N번" 같은 쉬운 말)를 쓴다.

## 왜 바꾸나 (사용자 피드백 + 분석)
일반 사용자가 "어렵다"고 했다. 원인:
1. **가정인지 사실인지 구분이 안 됨.** 맨 위 가장 큰 글씨가 "평가액 −1억 129만원"인데, 이건 아래 슬라이더(S&P500 −10%)의 결과다. 결과를 먼저 보고 놀란 뒤에야 조건을 발견한다.
2. **용어.** 베타, %p, "시장 움직임을 뺀 값", 소수점 계수 나열, CPI·FOMC·티커가 설명 없이 나온다. "(웹과 같은 값)"은 개발자 메모가 노출된 것.
3. **조작 불명확.** 칩 5개가 무엇을 바꾸는지, 슬라이더 범위가 어디까지인지 안 보인다.
4. **결론 없음.** 전부 음수인데 가운데 축 막대라 절반이 비고, "−0만원" 같은 값이 보인다. 일정 카드는 위 계산과 연결이 없고 탭바에 가려진다.
5. **다른 탭과 충돌.** 금리를 0.5%p 올리면 이 화면은 NVDA가 오른다고 하고(시장 제외 일별 잔차 회귀), 금리 시나리오/금리 충격 테스트 개선안은 "성장·기술주가 금리에 크게 흔들려요"(금리→이익 경로, 3년)라고 한다. 계산이 달라서지만 사용자에겐 앱이 스스로 모순으로 보인다.
6. **다른 탭(내 목표·목표일 전망·금리 충격 테스트 개선안)은 이미 쉬운 말 + 프리셋 + "10번 중 N번" 언어**인데 이 탭만 통계 언어다.

## 이 탭의 자리 (포지셔닝)
| 탭 | 답하는 질문 | 시간 |
|---|---|---|
| 내 목표 / 내 길 | 10억에 닿을까? | 3년 |
| 목표일 전망 | 목표일에 얼마일까? | 3년 |
| 금리 시나리오(개선안: 금리 충격 테스트) | 금리가 바뀌면 목표가 흔들릴까? | 3년 |
| **외부 요인** | **바깥에서 무슨 일이 생기면, 지금 내 돈이 얼마나 움직이나?** | **오늘~한 달** |

외부 요인 = "뉴스 번역기". 목표·확률 이야기는 하지 않고 해당 탭으로 연결만 한다.
이 탭에만 있는 강점 3가지를 앞으로 꺼낸다: ① 여러 요인을 같은 단위(만원)로 비교 ② 종목끼리 상쇄되는 모습 ③ 일정·뉴스와 바로 연결되는 짧은 시간 단위.

## 화면 1 — 외부 요인 메인 (`Main.dc.html`, 위→아래)
1. **헤더**: 뒤로 + "외부 요인". (지금의 점 8개 페이지 표시는 없앤다)
2. **질문형 제목**: "바깥에서 무슨 일이 생기면, 지금 내 돈은 얼마나 움직일까요?" + 한 줄 설명 "지난 3년 동안 실제로 하루하루 움직인 만큼으로 계산해요. 목표까지의 영향은 목표일 전망에서 봐요."
3. **오늘의 이벤트 카드(어두운 배경)**: 가장 가까운 일정(예: 오늘 · 미국 물가(CPI) 발표) → "예상보다 높게 나오면, 내 자산은 보통" → 큰 숫자 "약 −1,500만원" → 근거 한 줄(시장 보통 ±1.5%, 내 종목은 시장의 2배쯤) → 버튼 [이 상황 미리 보기](요인 상세를 그 값으로 열기) · [내일 결과 알림]. 45일 안에 일정이 없으면 이 카드는 숨김.
4. **"내 자산을 흔드는 요인" 순위 (이 탭의 핵심, 새로 추가)**: 요인마다 '보통 한 달에 움직이는 만큼'으로 맞춰 만원 단위로 비교.
   - 줄마다: 순위 원 · 요인 이름 · ±금액 · 막대(1위=100%) · 한 줄 해석 · 오른쪽 화살표(누르면 요인 상세).
   - 관계가 약한 요인은 순위 "–", 금액 대신 회색 "뚜렷한 관계 없음".
   - 아래 요약 상자(연초록): "내 자산이 흔들리는 이유는 대부분 미국 시장 하나예요…" — 순위에서 자동으로 만드는 문장.
5. **"그때 그 일이 지금 일어나면" (과거 재생)**: 실제 기간 3개(2020.3 코로나 급락 / 2022 금리 급등기 / 2024.8 엔캐리 청산). 카드마다 기간·이름·지금 구성에 적용한 합계, 그때 움직인 요인 칩, 해석 한 줄(환율이 손실을 막았는지 키웠는지 — 막았으면 초록, 키웠으면 주황 글씨).
6. **"다가오는 일, 미리 겪어보기"**: 45일 일정 줄마다 날짜·D-day·이름·"(무엇)을 통해 보통 ±N만원" + [미리 보기] 버튼. 아래 체크 "발표 다음 날, 실제로 얼마나 움직였는지 알려주기".
7. **"지난 일 돌아보기"**: 가장 최근 지난 일정의 '미리 본 범위' vs '실제로는' 두 칸 + 판정 문장("미리 본 범위 안이었어요…").
8. **꼬리 안내**: "예측이 아니라 '만약에'를 보는 화면이에요…"

## 화면 2 — 요인 상세 (`Factor.dc.html`, 미국 금리 예시, 위→아래)
1. **헤더**: 뒤로(메인) + "외부 요인 · 미국 금리".
2. **질문형 제목** "미국 금리가 이렇게 되면, 지금 내 돈은 얼마나 움직일까요?" + 기준 설명(10년물, 시장 전체 움직임 뺀 값).
3. **프리셋 2×2 버튼** (금리 충격 테스트 개선안과 같은 모양): 내린다 −0.5%p / 오른다 +0.5%p / 작년만큼 또 오른다 +1.1%p / 2022년처럼 급등 +2.5%p. 선택 = 초록 채움.
4. **판정 카드(어두운 배경)**: 조건 문장 → 큰 판정 문장("거의 그대로예요 / 조금 늘어요 / 조금 줄어요") → "내 자산 +5만원 · +0.01%" → **오르는 쪽 / 내리는 쪽** 막대 2개(합계 금액) → "종목끼리 반대로 움직여서 거의 상쇄돼요…" (상쇄가 이 탭만의 가장 강한 메시지).
5. **큰 변화 경고(주황 상자)**: |변화|가 지난 3년 범위를 크게 넘는 프리셋(목업: 2%p 이상)에서만 "이만큼 큰 변화는 지난 3년 안에 거의 없었어요…".
6. **"종목별로 보면"**: 가운데 축 막대(왼쪽 내림=파랑, 오른쪽 오름=빨강) + 종목명 + 말 라벨(금리가 오르면 함께 올랐어요 / 내려요 / 뚜렷한 관계 없음) + 금액 + 신뢰도 한 줄("10번 중 7번 이 방향이었어요"). 신뢰도 낮은 종목은 흐리게(불투명도 0.55).
7. **"금리 충격 테스트와 숫자가 왜 달라요?"**: 두 칸 비교(이 화면 = 그날 실제 움직임 / 금리 충격 테스트 = 3년 이익 경로) + 한 줄 + [목표에 미치는 영향 보기] 버튼.
8. **다가오는 금리 일정**: 이 요인 관련 일정만.
9. **"금리 변화 직접 정하기"** 접힘 줄 — 지금의 슬라이더는 여기 안으로 들어간다.
10. 꼬리 안내.

다른 요인 상세는 같은 틀에 프리셋만 바꾼다(목업 없음, 제안값):
- 미국 시장: 흔한 나쁜 날 −2% / 나쁜 한 달 −8% / 2022년처럼 −25% / 좋은 한 달 +8%
- 원/달러: 1,300원 / 지금 / 1,500원 / 2022년처럼 +20% — 시장 급락 때 손실을 막아주는 역할을 꼭 문장으로
- 유가·금값: ±10% / ±30% — 관계가 약하면 판정 카드에 "뚜렷한 관계 없음"을 크게

## 목업과 실제 구현의 차이 (반드시 바꿀 것)
### 숫자 출처
| 목업 값 | 목업에서 어떻게 만들었나 | 실제로 필요한 것 |
|---|---|---|
| 총 평가액 5억 1,472만원 | 사용자 스크린샷 값 | `m.total` / `valuation()` |
| 금리 종목별 +0.1%p당 NVDA +43.6만, SPCX −31.6만, TSLA −11만 | 스크린샷(+0.5%p 결과)에서 역산 | 기존 `beta("rate", id)` × 평가액. 지금 식 그대로 |
| 요인 순위 ±4,560만 / ±1,220만 / ±3만 | **예시값** | 요인별 '보통 한 달 변화'(지난 3년 월간 변화의 표준편차 등) × 포트폴리오 민감도. **요인 월간 변동폭은 지금 stats.json에 없다** |
| 원/달러 ±1,220만 | 달러 자산 약 4.9억 가정의 예시 | 달러 비중 × 환율 월간 변동폭. 환율은 `fx.last`가 아니라 매매기준율 기준으로 맞출지 결정(architecture.md 91행 참고) |
| 과거 재생 3개 기간의 지수·금리·환율 변동, 합계·"막아줬어요" 금액 | **예시값** | 기간별 실제 요인 변화(고정 표 또는 data/ 시세에서 계산) × 지금 종목 민감도. 기간 내 데이터 없는 종목 처리 규칙 필요 |
| 일정별 "보통 ±N만원", CPI 카드 −1,500만원 | **예시값** | 일정 종류별 '그날 보통 시장 변화'(과거 발표일 S&P 일간 변화의 중앙 절댓값 등) × 시장 민감도. 근거 데이터 없음 → 새로 만들거나 고정 상수 + 출처 |
| 신뢰도 "10번 중 N번" | **예시값** | 웹 `factorBetas().stat[fk][t].corr`는 있으나 **stats.json에는 beta만 내보냄**(`tools/site_stats.mjs` 63행). 앱이 쓰려면 corr(또는 부호 일치 비율·구간별 안정성)을 stats.json에 추가해야 함 |
| 지난 일 돌아보기 ±800만 vs −620만 | **예시값** | 발표 전 계산값 저장 + 다음 날 실제 평가액 변화. 저장소·알림 새로 필요 |

### 화면·동작
- 지금 앱: `ios-app/Naeilo/Views/AnalysisDetail.swift` `ExternalView`(321행~). 요인 칩 + 슬라이더 + 고정 상단(`PinnedLayout`). 새 안은 **고정 상단 없이 스크롤**, 요인 상세는 별도 화면(메인에서 push).
- 지금 웹: `web/app.js` "외부 요인 (사건)" 섹션(1380행~), `renderSens`(1482행), `factorBetas`(1448행). CLAUDE.md 규칙상 **웹에 같은 화면이 있으면 앱 숫자는 웹 기본 옵션과 같아야** 한다 → 순위·과거 재생·일정 금액 계산식은 웹 `model.js`와 앱(`SiteCalc`)에 같이 넣고 parity 도구 범위도 검토.
- 목업 아트보드는 390px 고정 폭·고정 높이. 실제는 SwiftUI 가변 레이아웃. 색은 목업 hex를 그대로 쓰지 말고 `Theme.swift` 토큰에 맞추되, 내 길 B안과 같은 초록(#2B6B5D 계열)을 쓴다. 지금 화면의 주황 칩은 없앤다.
- 목업 "SGOV · 국내 주식" 한 줄은 자리 표시. 실제는 보유 종목마다 한 줄, 관계 약한 종목은 흐리게(또는 "나머지 n개 · 뚜렷한 관계 없음"으로 묶기 — 결정 필요).
- "뚜렷한 관계 없음" 기준(예: |corr| < 0.1 이거나 영향 < 평가액의 0.1%)과 "거의 그대로예요" 기준(목업: |합계| < 50만원)은 **임시값**. 금액 고정이 아니라 평가액 비율로 정할 것.
- 큰 변화 경고 기준(목업: 2%p)도 임시값 → 요인별 '지난 3년 최대 월간 변화' 같은 근거로.
- "목표에 미치는 영향 보기"는 목업에서 `href="#"`. 실제 연결: 금리 → `AnalysisRoute.rateScen`(금리 시나리오), 그 외 → `.forecast`(목표일 전망). 금리 충격 테스트·목표일 전망 '개선안'은 아직 구현 전일 수 있으니 이름은 지금 화면 이름을 따른다.
- [내일 결과 알림], 다음 날 회고 체크박스: 기존 일정 알림(`Remind.swift` `MarketEvents`, `RemindViews.swift`)과 합칠지 결정.
- 슬라이더는 없애지 않고 "직접 정하기" 접힘 안으로. 범위는 지금 값 유지(시장 ±30%, 금리 ±1.5%p 등).
- 문구 규칙: "종목 + 금액 + 시점" 조언 금지(CLAUDE.md). 목업 문구는 모두 '만약에' 결과라 괜찮지만, 순위 해석·요약 문장 자동 생성 시 "줄이세요/사세요" 같은 표현이 나오지 않게.
- 모든 요인을 독립으로 더하지 않는다: 과거 재생은 실제로 함께 움직인 값을 쓰고, 순위는 요인별 단독 영향임을 문구로 분명히.

## 사용자 결정이 필요한 것 (다음 스레드가 계획 제안 때 질문)
1. 앱 먼저 / 웹 먼저 / 동시 — parity 규칙 때문에 계산식은 함께 바뀌어야 함.
2. 순위 단위 "보통 한 달" 확정 여부(대안: 하루, 1년).
3. 일정별 '보통 움직임' 데이터를 만드는 방법(과거 발표일 계산 vs 고정 상수).
4. 다음 날 회고·알림을 이번 범위에 넣을지, 다음 단계로 미룰지.
5. 관계 약한 종목 표시 방식(흐리게 한 줄씩 vs 묶기).
